# Real R notebook plot capture and portable persistence

The browser workbench now captures **actual R graphics** produced by its existing
R execution engines, rather than limiting notebook plot persistence to Python.
For browser webR, bounded `ImageBitmap` graphics are rasterized into PNG
without closing the live bitmaps before the cell renderer receives them.
For native localhost Rscript, the production `/api/plot/r` SVG snapshot
generated by the real per-execution R plot device is rasterized by the browser
after that cell executes. No plot is fabricated from the source.

Each captured PNG is checked against the 512 KiB portable `.fsnb` per-image
limit and a 2,048-pixel dimension ceiling; notebook runner limits of eight
plots per cell, 32 per execution and 8 MiB aggregate still apply. Scratch
canvases are released. Failed/oversized rasterization is discarded without
pretending a plot was saved. PDF-only native R devices cannot yet be converted
to PNG in this browser path.

The same PNG is rendered in the real notebook cell, stored in browser output
recovery and exported to `.ipynb` / `.fsnb`. Importing a saved notebook
restores display-only PNG output without running R or restoring its variables.

Reproduce with the real server and Chromium:

```sh
npm test
python3 scripts/verify_native.py --require-r
node tests/native_ui.mjs
```

The physical Chromium regression runs native Rscript `plot()` inside a notebook,
checks the decoded PNG, downloads `.fsnb`, checks the saved PNG bytes and
imports the bundle without any additional interpreter request. Node tests
exercise webR bitmap conversion, invalid/oversized payloads and native SVG
rasterization boundaries. Linux/macOS CI and actual browser results must be
reported separately. This does not establish full RStudio parity, PDF-only
plot persistence or independent macOS browser interaction.
